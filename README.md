# Learning Route Value to Improve a Ticket to Ride: Europe Optimizer

This repository contains Chengzong Liu's CSE 163 final project for Summer
2026. The project combines three Ticket to Ride: Europe datasets, derives
geographic and graph features for every destination ticket, evaluates
leakage-free machine-learning models, and compares a printed-point optimizer
with an optimizer driven by out-of-fold learned ticket values.

Public repository:
[cse163-ticket-to-ride](https://github.com/liuchengzong291817-ui/cse163-ticket-to-ride)

## Repository contents

### Python programs

- `analysis.py` is the runnable entry point for the complete project. It loads
  the data, creates the feature table, runs repeated nested cross-validation,
  evaluates matched optimizer scenarios and blocked-edge robustness, and
  writes every reported CSV and figure.
- `data_features.py` loads and validates the three input files, constructs the
  undirected Europe route graph, runs Dijkstra's algorithm, and derives the
  geographic, efficiency, redundancy, detour, tunnel, ferry, and overlap
  features used in the analysis.
- `modeling.py` compares a fold-trained mean baseline, standardized Ridge
  regression, and random-forest regression with repeated nested
  cross-validation. It produces held-out metrics, averaged out-of-fold
  predictions, selected hyperparameters, and held-out feature importance.
- `optimizer.py` builds shared route networks under the 45-train limit. It
  supports deterministic printed-point and learned-value comparisons,
  matched candidate-pool simulations, and post-hoc or adaptive blocked-edge
  stress tests.
- `test_project.py` tests the data checks, graph algorithms, derived features,
  target-leakage safeguards, nested cross-validation outputs, optimizer budget
  and connectivity constraints, matched simulations, reproducibility, and
  blocked-edge behavior.

### Data and supporting files

- `data/cities.csv` contains 47 Europe cities and their longitude and latitude.
- `data/routes.csv` contains 90 playable routes and their carriage, color,
  tunnel, and locomotive requirements.
- `data/destinations.csv` contains 46 destination tickets and their printed
  point values.
- `requirements.txt` lists the Python packages needed to reproduce the
  analysis and run the quality checks.
- `figures/` receives the figures generated by `analysis.py`.
- `outputs/` receives the result tables generated by `analysis.py`.
- `report/` contains the final written report and its source files.

The three original CSV files come from Leon Simon's public
[Data & Analysis of Ticket to Ride: Europe](https://github.com/leonsi7/ticket-to-ride-europe)
repository. Copies are included under `data/`, so no separate data download is
needed.

## Requirements

The project requires Python 3.11 or newer and the packages listed in
`requirements.txt`:

- NumPy
- pandas
- Matplotlib
- seaborn
- scikit-learn
- flake8, for the code-quality check

No Jupyter notebook or external service is required. All commands below must
be run from the repository root so that the relative paths `data/`,
`figures/`, and `outputs/` resolve correctly.

## Clean-clone setup

Run the following commands in a terminal:

```bash
git clone https://github.com/liuchengzong291817-ui/cse163-ticket-to-ride.git
cd cse163-ticket-to-ride
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On Windows PowerShell, activate the environment with this command instead:

```powershell
.venv\Scripts\Activate.ps1
```

If the command `python` refers to Python 2 on a system, use `python3` in each
command instead.

## Reproduce the full analysis

From the repository root, with the environment activated, run:

```bash
python analysis.py
```

The command starts from the included raw CSV files and regenerates all tables
and visualizations used in the report. Existing generated files with the same
names are replaced. The script creates `outputs/` and `figures/` if necessary.

### Expected CSV outputs

- `outputs/dataset_summary.csv`: row, column, and missing-value counts for the
  three raw files and combined feature table.
- `outputs/rq1_summary.csv`: seven-number summaries for the principal RQ1
  variables.
- `outputs/feature_table.csv`: one row per destination ticket with the raw
  outcome and all derived map features.
- `outputs/model_metrics.csv`: repeated nested-cross-validation MAE and
  R-squared summaries for the mean baseline, Ridge, and random forest.
- `outputs/oof_predictions.csv`: averaged out-of-fold prediction from each
  model for every destination ticket.
- `outputs/selected_hyperparameters.csv`: Ridge and random-forest settings
  chosen within each outer training fold.
- `outputs/feature_importance.csv`: aggregated standardized Ridge coefficients
  and held-out random-forest permutation importance.
- `outputs/optimizer_trials.csv`: trial-level results for the printed-point
  baseline and learned out-of-fold optimizer under identical candidate pools.
- `outputs/optimizer_summary.csv`: paired median, quartile, and difference
  summaries for the two optimizer methods.
- `outputs/blocked_edge_robustness.csv`: post-hoc and adaptive results after
  important route edges are blocked one at a time.

### Expected figure outputs

- `figures/eda_relationships.png`: exploratory relationships among printed
  points, minimum train cost, efficiency, and route fragility.
- `figures/model_comparison.png`: held-out model metric comparison.
- `figures/oof_predictions.png`: printed points versus out-of-fold predicted
  points.
- `figures/feature_importance.png`: held-out model-interpretation summary.
- `figures/optimizer_comparison.png`: matched baseline-versus-learned optimizer
  metrics.
- `figures/optimizer_robustness.png`: blocked-edge retention and adaptive
  re-optimization results.
- `figures/selected_networks.png`: representative Europe networks selected by
  the two value functions.

## Run the tests

Run the complete automated test program from the repository root:

```bash
python test_project.py
```

A successful run ends with:

```text
All tests passed!
```

The tests include small hand-checkable graph cases as well as full-data and
integration checks. In particular, they verify that target-derived columns
such as `Points`, `points_per_train`, and `high_value_edge_overlap` are not
model predictors; each reported learned value is produced out of fold; all
selected networks remain within 45 trains; and blocked routes are never used
by adaptive plans.

## Run the code-quality check

Run flake8 on every submitted Python module:

```bash
python -m flake8 analysis.py data_features.py modeling.py optimizer.py test_project.py
```

A successful check produces no terminal output.

## Reproducibility

The full analysis uses random seed `163` for cross-validation, random-forest
fitting, permutation importance, and matched optimizer candidate pools. The
same cross-validation folds and candidate pools are reused for each compared
method. Machine-learning preprocessing and hyperparameter selection occur
inside training folds, and optimizer comparisons use averaged out-of-fold
predictions rather than in-sample predictions. With the listed package
versions and included data, rerunning `python analysis.py` reproduces the
reported numerical results and output files.
